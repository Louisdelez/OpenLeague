# Contribuer à OpenLeague

Utiliser une branche dédiée et une pull request. Préserver les travaux existants. Relier chaque changement à un comportement attendu de LoL 4.20 et distinguer ressource native, réparation et reconstruction.

Suivre le [workflow Git/GitHub](docs/GIT_WORKFLOW.md) et le [versionnement](docs/VERSIONING.md). La PR utilise le modèle du dépôt, un titre Conventional Commits et une description renseignée. Les hooks optionnels prek et les contrôles GitHub appliquent la même politique de dépôt. Les versions restent synchronisées entre workspace, launcher et configuration Tauri ; les packs d'assets existants restent séparés du code.

Exécuter les vérifications adaptées ; documenter commandes, résultat, environnement et limites. Pour un effet visuel ou audio, conserver une observation réelle. Pour le réseau, vérifier les informations cachées, départs et reconnexions. Ne pas écrire qu'un champion ou mode est complet sans ses scénarios d'acceptation.

Les contributions originales au code sont proposées sous MIT. Ne contribuer aucun contenu tiers sans droit de redistribution compatible et mentions de provenance. Conserver les licences des dépendances.

Ne pas soumettre secrets, identifiants de session, caches de compilation ou logs privés. Ne pas ajouter de services externes ou de changement d'architecture sans expliquer la nécessité. Les noms et contrats historiques doivent rester traçables.
