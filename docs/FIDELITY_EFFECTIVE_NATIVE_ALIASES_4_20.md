# Alias natifs effectifs et tables de graphes

Les quatre emplacements de base des 122 champions sont interrogés dans les tables construites par le code original. Les 488 valeurs effectives proviennent du wrapper natif V28 conservé ; lower_bound, comparaison de chaînes, recherche par numéro, constructeur et destructeur originaux s’exécutent sur les 122 graphes candidats. La composition champ→table est un contrat de sonde de référence : le vrai chemin d’appel d’un cast n’est pas observé ici.

Résultats : 460 recherches donnent une clé de nœud et 28 ne trouvent pas d’alias. Quatorze correspondances sont retrouvées par l’équivalence de casse du comparateur original ; aucune n’avait un nœud sérialisé de même casse exacte. Le champ absent de BraumE, SionQ et YasuoQW reste le défaut Attack1 du wrapper, qui trouve un nœud du même nom ; cela n’attribue pas une animation d’attaque à ces sorts. Les huit chaînes explicitement vides restent vides et manquent dans les tables. Vingt autres alias nommés manquent aussi : aucune règle « pas d’animation » n’en est déduite. Le corpus exécute 6 683 315 instructions originales à 1 898 PC, sans accès mémoire non mappé ; chaque graphe finit sans allocation invitée restante.

Renekton n’avait aucun graphe dans la précédente sélection qui exigeait l’égalité de tous les champs de skin. Le fichier existe : les deux configurations de même ChampionSkinID désignent RenektonBase.blnd. Seuls ChampionSkinName et SkinScale diffèrent. Le champ Animations commun est conservé avec ses deux provenances ; le manifeste et deux appels du wrapper de configuration original le confirment. Les quatre alias Spell1..Spell4 trouvent des nœuds de type1. Ni la priorité de configuration complète, ni le nom/échelle effectifs ne sont résolus. La première préparation avec quatre jointures absentes reste conservée et explicitement remplacée pour ce champ seulement.

41 contrôles de qualification passent, dont 23 refus d’observations altérées. Onze contrôles de limites vérifient notamment la chaîne vide, un nom absent, les variantes de casse, la clé zéro valide et la sentinelle none=0xFFFFFFFE séparée d’un index. Deux refus concernent uniquement les entrées de la sonde (non ASCII et trop longue), pas une erreur native historique. Les sources, identifiants, journaux et anciennes preuves sont conservés.

Le consommateur maintenu audit_effective_native_aliases.py est installé et exécuté. Les 488 exigences de présentation, dix ROLE et trois SYS sont reliées ; 33 inconnues existantes (15 de rôles et 18 de présentation) sont précisées, toutes ouvertes avec leur historique. Aucun rôle courant, clip, asset ni code Rust/C de production n’est changé. Cases, notes, révisions et acceptations sont conservées.

Restent l’appel réel champ→cast, le chargement ANM/ressources, l’activation, le choix des enfants, les poses, la lecture et les autres objectifs du Goal. Les feuilles de tas, corps/handles, état d’allocateur et FS restent les frontières déclarées de V30 ; les adaptateurs du getter de configuration restent séparés. Aucun client historique complet, runtime/NLS historique ou jeu complet n’est qualifié.
