Le geste gauche convertit par la projection Map10 centrée zoom1, vérifie le propriétaire CameraLock, demande false/Origin::Minimap puis change uniquement X/Z du focus, en conservant Y. La caméra peut inspecter une case non marchable. Le droit envoie une Move ordinaire seulement si ground(point) existe ; sinon abandon local sans message dédié, sans cellule de remplacement. La commande serveur conserve ses propres refus vie/stun/déplacement forcé/ultime/chemin. Le contexte minimap ne filtre pas la vie : une Move peut être émise puis refusée pour mort ; la caméra libre est distincte. Comparaison statique conditionnelle, pas défaut graphique nouvellement observé.

Le bouton caméra utilise index=locked*3+appearance. CameraIcon_On est le survol du préfixe déverrouillé ; ce nom ne signifie pas locked=true. Les six sprites sont deux familles × repos/survol/pression pour un seul contrôle. Une release conserve owner/révision/valeur attendus ; StaleRevision préserve le changementY plus récent. Refus sur stderr, aucun sprite de rejet dédié identifié. Hors disponibilité le bouton est retiré ; hors human_enabled le geste est annulé, tandis que le verrou existant peut suivre en arrière-plan/shop ouvert selon politique locale. Cela ne prouve ni persistance disque ni callback natif.

Les gardes D/F ciblés existent déjà ; Heal reste l’exception sans sélection monde derrière l’overlay. Ni Move ni Camera ni Heartbeat ne sont un ping. G/V et les accords Alt/Ctrl ne sont pas déclarés universellement inertes : aucun dispatcher ping actuel n’est établi ; ne pas déduire qu’ils ne déclenchent aucun autre comportement local.
