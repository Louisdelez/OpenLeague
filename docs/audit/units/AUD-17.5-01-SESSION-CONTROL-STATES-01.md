## R3 — Consommateurs et états

Après refus corrélé « pause disabled by local match host », le message de refus s’affiche mais Running rend encore Pause,true ; une nouvelle pression peut reproposer la demande. Ce comportement est testé et l’écart PAUSE-DISABLED-FEEDBACK-01 reste ouvert. Le flag local allow_pause et le budget serveur ne constituent pas une permission historique par mode.

Continue ne transmet aucune commande réseau : visibilité depuis résultat/membre local/délai, armed sur Pressed puis dismissed sur release intérieure ; le Splash est retiré dans la même Update avant le tableau. Return est un bouton enfant du tableau au-dessus du HUD, visible seulement après dismissed et correspondance session/membre du résultat figé. Il émet AppExit::Success, puis on_exit/départ ; erreur secure conserve reprise, erreur legacy garde départlegacy. Leave/Retired est un départ individuel, jamais un vote d’équipe.

Les fonctions Continue/Return n’exigent pas explicitement fenêtre principale focalisée ni lease de pointeur par epoch, contrairement au contrôle pause. La visibilité Continue ne compare pas connection.session au résultat, alors que Return le fait. Comparaisons statiques conditionnelles, pas bugs GUI observés ; politique de contexte et cas négatifs à qualifier. Les gardes voulus pour un bouton de sortie terminal ne doivent pas être inventés depuis ceux d’une commande de combat.
