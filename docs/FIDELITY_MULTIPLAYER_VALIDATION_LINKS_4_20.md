# Validation multijoueur — traçabilité V141

Existing legacy loopback,batched delay,stale replay and fixture journal do not establish six graphical clients,LAN,fixed latency,loss/reordering,contested resume or end-to-end result equality.

## SYS-20.5-01

Existing producer exercises six legacy UDP sockets within one Python process.

Limites : Six independent ordinary graphical clients with current transport remain unqualified.

## SYS-20.5-02

Inspected multi-peer probe is explicitly loopback.

Limites : This source does not exercise multiple LAN machines; machine identities and cross-host traces remain required.

## SYS-20.5-03

Proxy holds downstream datagrams and releases queued packets when another packet arrives.

Limites : This is not fixed latency on every packet or bidirectional calibrated delay.

## SYS-20.5-04

Fixture script explicitly replays stale unchanged datagrams after a new handshake.

Limites : Loss and reordering across ordinary matches/current session protocol remain unqualified.

## SYS-20.5-05

Diagnostic checks new session acceptance with the same graphical client process.

Limites : New fixture session is not resuming the same player during a contested objective.

## SYS-20.5-06

CPU test compares frozen result and serialized snapshot including inventory and gold.

Limites : Direct state setup is not end-to-end comparison of six live clients and final server result.

## SYS-20.5-07

Producer writes a diagnostic event journal at cleanup.

Limites : Journal producer is legacy/fixture scoped; protocol version and exact source/binary manifest must accompany future ordinary network archives.
